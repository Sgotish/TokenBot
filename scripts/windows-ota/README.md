Windows OTA v1 uses the TokenBots desktop shortcut. Every cold launch applies the newest staged release, then checks the stable HTTPS feed asynchronously. A full install registers the hook. Older copies use the one-time bootstrap linked from the website docs. This channel is for the private TokenBots desktop copy; upstream MSIX releases still require compatibility review and signature checks.

2026-11-06: release 2026110601 adds browser MCP and two skills through signed external assets. The manifest remains below the legacy 4 MiB limit. Assets are restricted to hash-named HTTPS URLs on tokenbots.top, a 24 MiB cap, no redirects, exact size and SHA256, and a 60-second background download timeout. Old clients first stage the manifest, then install the new transport on the next cold launch without marking the release installed until the asset is ready. A subsequent cold launch installs it. Thus a v1 migration can require three cold starts, with background downloads allowed to finish between starts. Do not restart a working task automatically. An already upgraded transport normally needs two cold starts (fetch then apply).

The feature installer rolls back config, image helper and both skill directories on failure, while retaining the upgraded transport. No model/key/auth/billing changes. Private rollback backups stay inside the dedicated profile. An installed release cannot be downgraded by restoring an older feed: publish corrected code under a higher version if rollback is needed. Runtime download is automatic; users do not run a ZIP installer. Installation on a test Windows runner is not proof that a customer's device has received the release.

Acceptance: https://github.com/Sgotish/TokenBot/actions/runs/42241567513 (legacy transport bootstrap, real signed-asset HTTPS download, injected second-step rollback, successful install, idempotent apply, real Edge navigation/click/snapshot). Public feed and asset hashes verified after publication. No customer device remote session or third-party login tested.

To publish, prepare a clean directory containing only public files (flat names) and apply.ps1. The installer receives -AppDirectory. Make each release cumulative, idempotent and transactional: on failure restore modified files and propagate the error. A failed release is retried on a later cold launch. To roll back a bad release, publish corrected content under a higher version. Use a UTC YYYYMMDDNN sequence, greater than the highest published version.

Run node scripts/windows-ota/publish.cjs VERSION RELEASE_DIR OUTPUT_JSON PRIVATE_PEM with the website repository's app/static/windows-ota-v1.json as output. Keep the private Ed25519 signing key in the owner's private storage and back it up securely. Ship the signed JSON at /static/windows-ota-v1.json by atomic replacement and compare the public bytes. No customer config or credentials go into the release. Re-run node --test tests/windows-ota.test.cjs when changing the updater and verify on Windows before advertising native acceptance.
