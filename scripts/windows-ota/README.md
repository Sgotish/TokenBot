Windows OTA v1 uses the TokenBots desktop shortcut. Every cold launch applies the newest staged release, then checks the stable HTTPS feed asynchronously. A full install registers the hook. Older copies use the one-time bootstrap linked from the website docs. This channel is for the private TokenBots desktop copy; upstream MSIX releases still require compatibility review and signature checks.

To publish, prepare a clean directory containing only public files (flat names) and apply.ps1. The installer receives -AppDirectory. Make each release cumulative, idempotent and transactional: on failure restore modified files and propagate the error. A failed release is retried on a later cold launch. To roll back a bad release, publish corrected content under a higher version. Use a UTC YYYYMMDDNN sequence, greater than the highest published version.

Run node scripts/windows-ota/publish.cjs VERSION RELEASE_DIR OUTPUT_JSON PRIVATE_PEM with the website repository's app/static/windows-ota-v1.json as output. Keep the private Ed25519 signing key in the owner's private storage and back it up securely. Ship the signed JSON at /static/windows-ota-v1.json by atomic replacement and compare the public bytes. No customer config or credentials go into the release. Re-run node --test tests/windows-ota.test.cjs when changing the updater and verify on Windows before advertising native acceptance.
