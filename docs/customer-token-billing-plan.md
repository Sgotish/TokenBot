# 客户 Token 用量与计价研究方案

日期：2026-10-19（Europe/Berlin）。状态：研究与实施设计，尚未修改线上收费或客户菜单。

## 目标与现有基础

客户看到自己消费的 Token、费用及余额；运营者查看订阅号池余量、成本与利润。客户计费依据请求用量和价格表，不以共享套餐下降的百分比扣客户余额。

研究基线：远端 25b25b0 加上本地 Windows 安装修复 908d562。固定计费底座为 Sub2API v0.2.16；不是最新上游版本。

| 已有实现 | 目前边界 |
| --- | --- |
| 每客户独立外部身份、Sub2API 普通用户、各组内部 Key | 多个客户共用上游账号，客户账本仍可隔离 |
| 网站客户可建立多个外部 Key 别名 | 同一客户的别名映射到同一组内部 Key，现有统计是客户级，不是每个别名级 |
| collect_partner_usage.py 使用各客户自己的后台会话读取 /usage/stats 和 /usage | 明细快照只取最近 30 条，不是完整期间账单 |
| usage_snapshot.py 导出每条记录的输入、输出、缓存读取和创建数量 | 缺失字段目前默认 0；正式账单必须区分未知与真实零值，并核对输入字段语义 |

## 客户界面

以下仅为虚构示例，使用 USD 举例，不是报价或真实客户记录：

```text
我的用量                         统计期间：本月
已使用 1.20M Token               已结算 $1.0125
可用余额 $8.9875                待核对 0 笔

模型              普通输入     缓存输入      输出        已结算
GPT-6.1 Sol          200K         800K        100K       $0.6660
GPT-6 Astra           20K          70K         10K       $0.3465

查看调用明细 · 查看价格表
```

客户可切换最近 5 小时、本周、本月和自定义期间。5 小时是滚动统计，不宣称为套餐刷新窗口。自然周从周一开始；月份按自然月。账单时区明确显示并由平台配置；查询采用 [开始时间, 结束时间) 避免重复统计，底层时间统一存 UTC。

桌面菜单只放本月 Token、本月已结算、可用余额和明细入口；网页放完整表格与分页明细。新界面的 Plus/Pro 如继续保留，应说明它是线路选择；不会为每位客户分配整个账号的套餐余量。

号池百分比、实际账号标识、订阅成本和额度重置时间放运营后台。客户接口在服务端只返回自己允许查看的字段，不能只在前端隐藏管理员信息。

## 用量与金额口径

统一用量字段：普通输入 U、缓存读取 R、缓存写入 W（确有独立字段时）、输出 O；总量 T = U + R + W + O。

- 原始 OpenAI 响应的 input_tokens 通常包含缓存，需要规范化；Sub2API 数据库的 input_tokens 可能已扣除缓存，必须核对固定版本实现和真实响应后再映射，不能重复减缓存。
- 已包含在 output_tokens 中的推理 Token 不再加一遍。展示的输出不是只按用户看见的文字估算。
- 缺字段、异常负值、价格缺失、协议未识别标记为待核对；不可显示成零费用或把模糊用量自动收费。
- 流式请求根据最终用量记录结算。超时、取消、失败以及供应商已消耗但未完整交付的情况须有明确规则；内部重试不得无条件重复扣客户费用。

价格可以保存最终单价，也可以保存基准价和客户倍率；一次账单只能应用一次倍率。每个模型、速度和上下文档位独立定价，记录生效时间、币种与价格版本。

```text
客户费用 = (U×输入价 + R×读取价 + W×写入价 + O×输出价) / 1,000,000
```

上式使用最终售价。如果选择基准价格模式，则再乘一次客户倍率。内部金额使用 Decimal 或精确整数单位，汇总不能先把每条记录截断到两位小数。若启用工具/图片等独立收费，需另建项目，不能暗中混进文本 Token。

保留三个不同字段：报价模拟金额、实际结算金额、待核对状态。测试期即使模拟金额非零，实际扣费仍为零；不能把模拟值写成消费余额。

## 接入和账本

```text
客户外部 Key / 网站登录身份
→ 映射 Sub2API customer user_id 与内部 Key
→ 模型调用和 usage
→ Sub2API 权威用量记录与扣费账本
→ 客户范围内的期间聚合 / 分页明细
→ 网页与桌面显示
```

继续使用 Sub2API 为唯一实际扣费来源，桥接层、网站和桌面不各扣一遍。研究阶段建立可重算的报价模拟结果，不能建立第二套独立的实扣余额。

建议响应字段（待对照真实接口确定映射，不是已实现 API）：

- 期间：start、end、timezone、generated_at、是否数据完整。
- 汇总：请求数、U/R/W/O/total、已结算金额、模拟金额、待核对笔数。
- 模型分项：精确模型 ID 与上述汇总；请求的模型与实际计价模型如不同应可追溯。
- 客户余额：已入账余额、预留金额、可用余额、币种；没有接入真实账本时返回未知/未启用。
- 明细：唯一 usage/request ID、时间、模型、各类 Token、价格版本/倍率快照、金额与结算状态；不携带客户内容、完整 Key 或上游授权。

只从经过鉴权的身份映射客户，不接受浏览器任意指定其他 customer_id。价格版本和账单关联优先复用网关字段，缺失时用不可变附属元数据关联唯一 usage ID，不复制资金扣减。

期间汇总从完整账本按范围查询。若暂用分页采集，须按唯一记录去重并覆盖全部页面、处理延迟到达/冲正；最近 30 条只用于“最近调用”。余额准入以网关实时账本为准，不能使用一分钟前的展示快照决定是否有钱。

多 Key 别名第一阶段合并到客户总账并明确标注。若需要逐 Key 账单，需让别名映射到独立内部 Key，或在网关持久记录不可伪造的别名 ID 与请求 ID；不能凭现有聚合记录反推每个别名的历史消费。

## 实施顺序与验证

1. **核对实际账本。** 读取目标实例的模型价格、usage 字段、金额/余额含义和客户映射。对七个模型分别核查；未知价格不能回退为免费。对照最终响应、后台记录、客户统计三个位置，查明缺失字段。
2. **客户用量展示。** 增加期间聚合和分页明细；共享接口供网页及桌面使用。完善未知、陈旧、待核对状态与客户隔离。先保持现有试用免费。
3. **模拟计价。** 使用带版本的研究价格表，显示“模拟费用，未扣款”。比较不同倍率及客户实际使用构成；不得用曾举例的 20%/70%/10% 当真实业务数据。
4. **收费验收。** 核对实收充值/赠送折算、单次余额变化、流式中断、重复请求、并发余额不足、冲正和对账。确认完整收费规则后启用独立收费分组；当前免费测试组保持原用途。

必要验证：客户 A 无法读取 B；同客户跨组统计一致；Key 别名总账范围明确；缓存不重复计数；缺 usage/价格不自动变零；跨期、分页和延迟记录不漏重；重放不重复结算；同一条账单的金额与余额变动一致；模拟模式不改余额。

迁移兼容：网页与桌面原有字段需有版本兼容窗口，不能只改服务器导致旧安装包报错。展示与采集故障不能自动清空余额或补成全额；前端标明待同步。

## 套餐成本研究

客户计价不必等待“Pro 相当于多少 Token”的研究完成；实际售价是否有利润则需要真实销售量和成本。

```text
月经营结果 = 客户已消费对应的实收收入
           - 订阅费 - 备用 API/补充额度 - 运维/服务器 - 手续费/退款等
```

充值到账和未用余额不自动视为收入；测试初始化的 1 单位不是充值。

对各模型分别记录同一账号的 Token 构成、速度/推理设置、任务类型、额度前后值、重置点、其他并行使用和失败损耗。额度快照需要追加历史保存；当前采集器覆盖最新快照，不能仅凭最新百分比重建一周历史。

每百万 Token 消耗的额度百分点 = 同一窗口已用百分比增量 / (该窗口对应实测 Token / 1,000,000)。这是控制变量下的观测值，受到取整、更新延迟和负载差异影响，不是官方容量承诺。Pro 没有返回 5 小时窗口时，只报告 5 小时实际用量。

只在记录充分且没有混入其他调用时估计某模型的容量；不同模型共享同一账号额度，单模型满额估算不可相加。售价研究按实际销售构成和保守可售量复核；API 或额外 Credits 单价不能直接当订阅真实成本。
