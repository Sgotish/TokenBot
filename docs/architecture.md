# 技术选型与第一阶段范围

调研日期：2026-10-15。依据会议纪要与补充讨论整理的通用技术需求；会议原文和商业信息留在本地。

## 目标

客户已有外贸获客 Agent 开发能力。本期提供可测试的模型调用后端、账号管理、用量统计、接入资料和成本核算。先核实真实任务表现，再决定容量、定价和专属界面。

## 三个候选

| 项目 | 已核对的能力 | 本期取舍 |
|---|---|---|
| [Sub2API](https://github.com/Wei-Shaw/sub2api/tree/v0.2.16) | OAuth/API Key 类型账号、分组、黏性调度、并发限制、客户 Key、用量和运维界面 | 本期账号池管理底座，固定 v0.2.16 |
| [New API](https://github.com/QuantumNous/new-api) | 多供应商协议、渠道优先级、模型映射、用量/价格配置 | 若以后以官方 API 多渠道聚合为主，可另行评估；这次不叠加两套账本 |
| [One API](https://github.com/songquanpeng/one-api) | 标准化模型 API、Key 分发和基础渠道管理 | 可做基础中转，但本期优先验证账号池及原生客户端的适配 |

这是源码/文档能力比较，不是压测排名。附带 HTML 中的延迟、可用率、盈利数据缺少可复核测试记录，不用作本项目承诺。其 `latest` 镜像、默认密码、公开数据库端口等示例不直接照用。

## 调用链

客户 Agent → 客户专用 Key → Sub2API 的鉴权/分组/调度 → 已授权上游账号/API → 返回模型结果与 usage → 后台使用记录。

异步线索分类：完整任务上下文 → 本地持久化队列 → 同一客户接口 → 结果文件/安全统计。原生供应商 Batch 与本地队列为两条显式不同的路径。

## 上下文与故障原则

- 无状态请求须自带完整必要上下文；切换账号不会自动复制供应商保存的会话。
- 使用 `previous_response_id`、远端 conversation 或工具调用状态时，须保持同一会话/账号；换号后可能需要重建上下文。不能承诺“云端本地始终一样”。
- 本期批处理只接收完整 input 的独立任务，拒绝远端会话依赖；不接管客户电脑执行命令。
- 429 遵守 Retry-After 和有限重试；认证/授权失败隔离并人工处理。限流、封禁和容量用尽不通过自动建号或清空限制规避。
- 已开始流式响应的调用不盲目重放。网络超时或 5xx 的批任务标记 uncertain，人工核对账本后决定后续动作。

## 功能映射

| 要求 | 交付位置 | 验证要求 |
|---|---|---|
| 研究并选用账号管理底座 | 本文、upstream.lock.json | 已读源码和发行信息 |
| 独立测试版 | Compose、本机运行脚本 | 本机启动/登录验证；服务器部署另测 |
| 多账号、分组、用户及 Key | Sub2API 现有后台 | 协议确认后导入实际授权账号再测 |
| 号池健康与运维 | 原生 Ops + healthcheck.py + 运维手册 | 不把进程健康等同于模型可用 |
| Batch 异步任务 | tokenbot.queue、cli | 本地可靠性测试 + 实际上游验收 |
| 缓存命中及成本 | tokenbot.usage、economics | 缺字段保持未知；账单对账 |
| 人工测试 | acceptance.md | 运营者与客户签字，不用自动测试替代 |
| 配置/教程/示范 | client-guide.md、examples | 实际模型/客户环境需验证；录屏待真实接入 |

共享需求文档仍需访问权限核对。本期不迁移旧网站、不购买账号/服务器、不改客户套餐、不确认商业报价、不把所有模型降级到同一个默认模型。
