# 套餐容量与售价研究

研究入口规划为现有云实例的 `/research`，独立于客户 `/portal`。
只有部署验证完成后才算上线。代码提交或本机预览不是线上验收。
研究系统只读取数据，不修改客户倍率、余额、套餐或账号调度。

## 数据与估算

- 现有 `tokenbot-usage.timer` 继续刷新额度。研究采集器每 5 分钟读取其脱敏快照，
  不额外访问上游额度接口，也不发起模型调用。
- 管理员 `/admin/usage` 按 UTC 日期完整分页；首次回填约 31 天，后续至少重读两天，
  停机后覆盖停机范围。按日志 ID 幂等保存，只保存配置中的号池账号。
  总数变化、重复页、缺页、缺少稳定 ID、超时或超过 200 页均不推进“完整覆盖”。
  单次网络采集最多 45 秒；单请求最多 10 秒。高流量超过边界时需改为逐日分片扫描。
- 数据保存在 SQLite，保留 90 天。不保存提示词、回复、IP、邮箱、完整 DTO 或密钥。
  独立访问密钥与只读报告可供研究 Web 服务读取；数据库与管理员凭据仅 root 可读。
- 四种 Token 为互斥桶：普通输入、输出、缓存读、缓存写。
  固定上游源码的 `openai_gateway_usage.go` 在写日志前已经从输入中减去缓存读写，
  所以不能再减一次，也不能另加已包含在输出中的 reasoning tokens。
  缺失计数保留未知，该记录不参与校准。
- 相同账号和额度周期累积至少 5 个百分点、至少 30 分钟组成一段样本。
  快照间隔超过 15 分钟、重置时间明显改变、百分比下降均切断样本。
  样本前后保留 120 秒的结算保护范围；请求时长也纳入边界误差。
  边界不确定 Token 超过样本 25%、日志不全、字段缺失或生成媒体等样本不参与估算。
  不变的百分比不能证明免费；无 Token 的额度下降也不能换算容量。
- 每段按总消耗 / 总 Token 求系数，聚合使用总和之比，而非平均各段比率。
  至少 3 段且累计 15 个百分点后标记“已积累样本”；此前为“初步样本”。
  这是数据量门槛，不是统计置信保证。
- 混用多模型只计算当前混合负载。只有边界保护范围内模型、推理强度、速度都一致时，
  才另外归入对应模型组合。未知强度/速度明确显示 unknown，不能认为与另一组合可比。
  页面同时显示输入/输出/缓存比例。不能凭混合样本把额度按 Token 比例分给各模型。

计算公式：

```
k = 消耗额度百分点 / (实测 Token / 1,000,000)
完整窗口 Token = 100 / k * 1,000,000
30 天容量情景 = 周容量 * 30 / 7
每百万成本 = (月账号成本 + 分摊运营成本) / (月容量 / 1,000,000 * 可售利用率)
保本价 = 每百万成本 / (1 - 支付费率)
目标售价 = 每百万成本 / (1 - 支付费率 - 目标利润率)
```

页面初始成本 $100 来自运营者假设，不是查得的官方订阅价格。
利用率 70%、支付费率 3%、利润率 30% 也只是可修改情景。
5 小时只有实际用量和该窗口容量，不把 5 小时窗口直接乘成月额度。
上游只返回周窗口时，5 小时容量保持未知。

敏感区间假设每段额度端点差至少有 ±1 个百分点误差，并结合边界 Token。
它不是置信区间，也不能覆盖平台外调用、未知失败重试、上游额度规则变化等误差。
月容量是长期运行速率情景；短窗口、并发、速度和闲置会降低可售量。
同一账号的多个模型共享容量，账号成本只能计一次，各模型完整容量不能相加。
输入/输出/缓存独立售价尚未拟合。研究输出不能直接作为客户账单。

## 部署到现有 Ubuntu 实例

将已验证版本的 `tokenbot/`、两个研究脚本及三个 research systemd 单元同步到
`/opt/tokenbot-pilot`，保留 `private/`、`cloud.env`、数据库和现有客户文件。
确认现有 `private/collector.json` 包含账号映射和管理员登录，且额度采集 timer 正常。

```bash
cd /opt/tokenbot-pilot
sudo venv/bin/python scripts/install_capacity_research.py
```

安装器备份现有 Caddy 配置及已有研究单元到带时间戳的 `backups/capacity-research-*`。
创建独立随机访问密钥 `/var/lib/tokenbot-research/access.secret`，不在输出或 URL 展示。
复跑保留原密钥。研究页端口 8185 只绑定 loopback；Caddy 只新增 `/research` 路由，
保留客户网关 8181 和网站控制面 8184 的路由。先校验候选配置，再运行首轮采集和
本机鉴权检查，成功后才重载 Caddy 并启用 5 分钟研究 timer。
研究 Web 服务重启不影响推理桥接。安装失败不会自动覆盖客户数据或回滚客户注册。

通过既有的私密交付渠道交付 `access.secret` 文件。研究页手动输入密钥，
只保留在内存，不写 URL、Cookie 或 localStorage。使用 HTTPS；禁止公开分发密钥。
页面不含客户身份信息或管理员登录资料。API 无跨域许可、无写操作。

```bash
systemctl status tokenbot-research tokenbot-research-collect.timer --no-pager
systemctl status tokenbot-research-collect.service --no-pager
journalctl -u tokenbot-research-collect.service -n 20 --no-pager
```

验证公网 `/research` 可打开、无密钥访问报告返回 401、正确密钥可读取报告；
确认采集时间和账号标签正确，至少经过两轮定时采集，原客户 `/portal` 和模型发现仍可用。
不为凑样本消耗套餐；首次页面出现“正在积累样本”是正常结果。
上游日志字段或分页契约不同会停止推进完整覆盖，先核实实机协议，不能用猜测数据填充。

回滚：停止并禁用 `tokenbot-research-collect.timer` 与 `tokenbot-research.service`；
仅移除新增 research 路由，校验并重载 Caddy。若后来还有 Caddy 修改，手动合并，
不要直接恢复旧配置覆盖新路由。保留 SQLite 和密钥可继续历史研究。
