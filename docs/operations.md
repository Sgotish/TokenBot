# 部署与维护

## 独立部署

本地实例与原有网站无共享数据库/Redis/管理会话。所有本地监听仅限 127.0.0.1；不开放本地 Mac 给客户公网访问。Compose 与 macOS 本机启动方式二选一，不同时占用 8180。

首次管理员随机密码在 `.env` 或 `.runtime/local.json`。这些文件、数据库、JWT/TOTP 密钥都是私密运维资料。不要提交 Git 或放进共享需求文档。管理员首次协议确认由实际运营者完成，不允许脚本写库跳过。

## 上游接入

1. 后台完成运营协议确认后设置试用名称和描述，关闭开放注册、自助支付和不需要的外部嵌入。
2. 每个上游账号记录来源、授权范围、平台、并发上限、限流窗口及到期时间；凭据只填在管理后台。
3. 同一账号的不同 Key 不算独立容量。不要靠复制 Key 来提高上游账号限额。
4. 初始每账号/每客户并发建议从 1 开始测，依据真实数据提高。订阅额度按上游窗口观察，禁止假定每天固定 Token 量。
5. 同一个客户会话采用黏性路由。先测工具调用及多轮连续性，再验证故障后的行为。
6. 401/403、到期或禁用账号进入人工处理；429 按真实恢复时间等待，不定时自动清空限制。
7. 同时保存“请求模型 ID”和上游返回 ID；不能从一个兼容名称推断模型来源或质量。

## 健康与观测

`python3 scripts/healthcheck.py` 只验证进程接口，不消耗模型额度。它不等于模型可用性测试。原生后台 Ops、账号测试、使用记录用于人工检查真实请求。

建议试用期每日人工查看：成功率、429/401/403/5xx、首字延迟和总时长、按账号/分组/客户用量、缓存读取/写入、队列 uncertain 数量、客户余额与实际账单差异。

监控阈值先作为待校准项；不要预先宣传 99.9% 可用率。若加入定时账号探测，应设置专用模型、最大输出和每日预算；这次未创建无人值守付费探测或通知任务。

## 备份和回滚

Docker：在维护窗口停止 gateway 的写入，使用 PostgreSQL 的 `pg_dump -Fc` 备份；JWT/TOTP/配置和上游凭据需另做加密备份。不要用复制在线数据库目录替代一致性备份。Redis 是调度状态，恢复时需检查遗留并发占位。

本机测试版：

```bash
python3 scripts/backup_local.py
```

备份位于 `.runtime/backups/`，权限 600。此脚本生成 PostgreSQL 逻辑备份和运行配置归档，仍是敏感资料，搬到异地前自行加密。恢复到新数据库验证，不直接覆盖正在服务的实例。

升级前记录版本、账号数量、账本总额和模型权限，备份后在新的独立实例验证。出现数据库迁移后，单独降级程序可能无法回退；应恢复匹配旧版本的数据快照。禁止直接拉 `latest`。

## 上服务器前

需要明确试用服务器、域名和可用上游账号。本仓库不自行购买资源。

- 配置 HTTPS 反向代理；仅允许代理访问 8180，数据库与 Redis 不映射公网端口。
- 限制 `/admin` 管理访问；API 客户通过自己的 Key 调用。
- 流式接口关闭代理缓冲，设置与真实任务匹配的读取超时；验证取消请求能结束。
- 确认注册/支付开关、客户角色、额度/并发、备份可恢复和运维联系人。
- 在客户实际网络测试 DNS、TLS、首字时间、断流重连；海外本机测试不能证明国内连通性。
- 使用新的试用域名。旧站切换/数据迁移作为后续独立变更，需迁移计划、对账及回退验证。
