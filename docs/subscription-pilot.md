# 订阅账号接入试点

更新：2026-10-16。方向是订阅账号授权接入；不要求购买官方 API Key。目前两个不同账号已通过 OAuth 导入，后台显示 Pro 100 和 Plus，均通过 6.1 Sol 简短调用。分组调度和客户入口尚待验证；接入结果不表示取得转售授权。

## 三层分别管理

1. 上游订阅：Plus、Pro 账号分别通过账号授权接入；每个账号独立保留身份、套餐、剩余额度、重置时间及状态。
2. 平台调度：按已验证的模型权限和分组选择账号；记录请求对应的实际账号。长会话保持账号黏性，不能假定换号后远端会话仍然存在。
3. 客户入口：平台发放自己的访问 Key，用来鉴权、限制并发和记账。这与购买上游官方 API Key 是两件事。

试点先按 Plus 和 Pro 分组，逐个验证后才允许进入可调用组。不按订阅名称猜测模型权限、固定 Token 数、并发或 Pro 档位。起始测试并发为 1，属于待测配置，不代表官方承诺。

## 能力与授权边界

固定版本 Sub2API 中有 OpenAI OAuth 账号接入、套餐识别和账号调度代码；这只能证明软件有实现，不能证明任一账号在当前环境可调用或有商业分发权限。

OpenAI 当前提供在受支持应用中使用个人 ChatGPT 套餐的机制，不需要用户提供 API Key；商业应用集成有独立准入流程。个人条款还限制账号提供给他人、服务转售及绕过限制。因此，自有订阅不能直接当成对外销售的通用 API 授权；对外供给前须确认适用许可或商业安排。

- [官方：在其他应用中使用 ChatGPT 套餐](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites)
- [官方：个人服务条款](https://openai.com/policies/terms-of-use/)
- [Sub2API 固定版本 OAuth 实现](https://github.com/Wei-Shaw/sub2api/blob/v0.2.16/backend/internal/service/openai_oauth_service.go)

账号所有者应在官方授权页面核对应用和权限；不要在聊天、Git 或共享文档粘贴密码、Cookie、授权码、访问令牌或刷新令牌。Sub2API 的授权入口不应被描述为本平台已经获得官方商业认证。

## 第一轮逐账号记录

| 检查项 | 记录内容 |
|---|---|
| 身份 | 脱敏标签、套餐实际档位、授权来源、有效期 |
| 能力 | 实际成功的模型 ID、协议、流式与工具调用 |
| 容量 | 测试前后用量窗口、恢复时间、人工约定的最大测试量 |
| 连续性 | 5 轮上下文、工具结果、取消后第二次请求 |
| 故障 | 429 等待、认证过期暂停、管理员禁用；不自动清空上游限制 |
| 成本 | 订阅真实费用、实际任务量、服务和维护成本 |

测试先用合成资料。只有单账号结果可核对，才验证分组调度。任何失败都记录，不用换号隐藏失败或把所有请求重写成其他模型。

## 计费和 Batch 的变化

订阅自建试点的成本不再直接套用以前供应商的 0.4 倍。按月汇总订阅费、服务器、维护及支付等费用，再除以完成任务或实际用量做成本评估；对客户的价格单独确定。

本地异步队列只是逐项提交普通模型请求，不自带原生 Batch 折扣。当前订阅渠道不能假定支持 `/v1/batches`。缓存命中读取实际 usage，用来观察效率；不能从官方 API 的缓存价格倒推订阅扣额一定等比例下降。
